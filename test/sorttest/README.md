# How Flash's Array.sort breaks ties

The game's AI chooses between equally good moves by sorting candidate lists with ActionScript 2's
`Array.sort` and taking the first entry. That sort is not stable, so a copy of the AI that sorts
differently picks a different move whenever two options tie. Ties caused almost all of the wrong enemy
predictions (~3% of AI turns on Hard).

## The experiment
`sort_experiment.as` runs at the start of the game's first frame. It sorts 400 lists of 2-31 items with
lots of equal keys (generated by a seeded random sequence), and saves the resulting orders to a Flash
SharedObject. `flash_sort_result.txt` is the output from a real Flash Player 9 projector (run under Wine).

To reproduce it from your copy of the game:

```sh
scripts/sorttest.sh                      # builds game/sorttest.exe (needs scripts/setup.sh first)
wine game/sorttest.exe                   # close it after a few seconds; no input needed
python3 test/sorttest/read_sol.py > test/sorttest/flash_sort_result.txt
```

## The result
`analyze.js` regenerates the same 400 inputs; `search.js` tries ~2,000 quicksort variants and finds the
one that reproduces all 400 results:

```
quicksort, pivot = first element of the range
  i = lo + 1, j = hi
  loop: while i <= hi and cmp(a[i], pivot) <  0: i++
        while j >  lo and cmp(a[j], pivot) >= 0: j--
        if i >= j: break
        swap(a[i], a[j])
  swap(a[lo], a[j]); sort [lo, j-1] and [j+1, hi]
```

Only 138/400 results match a stable sort. `../lib.js` installs this algorithm in the test sandbox, and the
advisor's copy of the AI builds its lists exactly as the game does (same order, including duplicate
entries), so inside Flash it makes the same choice on every tie: `FIDELITY=1 node arena.js ai ...`
reports 100% of AI turns predicted exactly.
